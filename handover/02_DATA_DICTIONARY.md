# 02 — Data dictionary

Table shapes come from `migrations/*.sql` (final state after all migrations
applied — see `handover/schemas.sql` for the literal DDL). Row counts, spans
and sizes come from `docs/DATA_INVENTORY.md`, generated by
`src/monitor/inventory.py` at **2026-09-11 08:16 UTC** against the owner's real
`data/`+`db/` — this container has neither directory, so these are the
project's own most recent self-measurement, not independently re-verified here.

**Groups do not sum** (DATA_INVENTORY's own warning): group 1 (`stock_data`)
and group 4 (`price_spine`) are the same prices, one carried, one rebuilt.
Adding group totals double-counts ~190M rows.

## Universe, date range, frequency

- **Universe**: NSE + BSE listed equities, point-in-time (month-end rebalance,
  ranked by 20-session median turnover). 4,200 symbols in the reconciled spine,
  1,497 delisted before 2026-08-01.
- **Date range**: price spine 2005-01-03 → present (7,792,635 rows,
  `price_spine`, per 2026-09-11 inventory); deal data 2006-01-02 → present
  (bulk) / 2006-01-16 → present (block).
- **Frequency**: daily (trading sessions only — observed calendar, 5,358
  sessions, never a generated calendar; 3 of them are Saturdays a generated
  calendar would have dropped).

## Schema — key tables (see `handover/schemas.sql` for full DDL)

### `institutional_deals_clean` (DuckDB, `research_prod.duckdb`)
One row per raw deal. `raw == clean` count always holds — every row either
resolves or carries a non-NULL `ineligibility_reason` (zero silent drops).
Key columns: `deal_id`, `raw_deal_id` (FK), `security_id`, `participant_id`,
`trade_date`, `available_from` (TIMESTAMP — the field the whole study rests
on; empirically measured, not assumed), `side` (BUY/SELL), `quantity`,
`deal_price`, `gross_deal_value`, `adv20`, `deal_value_to_adv20`,
`same_day_round_trip_flag`, `eligible_for_research`, `ineligibility_reason`.
**5 of the declared flag columns** (`duplicate_group_id`,
`five_day_round_trip_flag`, `internal_transfer_flag`,
`promoter_related_flag`, `suspect_flag`) were FALSE/NULL on all 237,340 rows
as of the last audit — they exist in the schema but nothing populates them yet.

### `deal_forward_outcomes` (DuckDB)
One row per (deal, interpretation, horizon, recovery_factor). `exit_reason`
is one of `HORIZON|DELISTED|MERGED|SUSPENDED` — priced separately rather than
silently dropped (the predecessor's silent-drop-on-delisting bug was worth
roughly the whole measured effect). `recovery_factor`: headline 0.0,
sensitivity 0.25/0.50. Joined to `outcome_benchmark_returns` for all 6
benchmarks (`CHAR_MATCHED`, `NIFTY50_TR`, `NIFTY500_TR`, `NIFTY_MIDCAP100`,
`SMALLCAP_SYNTH`, `EW_TOP500`).

### `experiment_registry` / `study_result` / `family_charge` (SQLite, `governance_prod.sqlite`)
Append-only, trigger-enforced. `experiment_spec_frozen` (BEFORE UPDATE) +
`experiment_no_delete` (BEFORE DELETE) + `experiment_replace_is_not_an_amendment`
(BEFORE INSERT, migration 0003 — closes the `INSERT OR REPLACE` bypass fixed
2026-09-12) together make a registered spec (`spec_hash`, `hypothesis`,
`pass_bar`, `kill_criteria`, `test_count`, `holding_period`, `cost_policy`,
`benchmark_policy`) immutable once `status != 'DRAFT'`. `family_charge` has
its own `family_charge_monotonic` trigger — `trials_after` may never decrease
within a family.

### `participant_oi` (DuckDB, migration 0004)
F&O participant-wise open interest — **derivatives positioning, not
cash-market flow**; column names are prefixed `oi_`/`*_long`/`*_short` rather
than `flow_` specifically to prevent that confusion downstream. `category` is
CHECK-constrained to `FII|DII|Pro|Client|TOTAL` (`TOTAL` is a computed sum row
in the source, kept rather than dropped so a naive `GROUP BY` doesn't
silently double-count).

## What is missing from the data (as opposed to the code)

- **No official small-cap or broad-market total-return index series** exists
  in the warehouse (`NIFTY500_TR` — the config's own declared headline
  benchmark — has no source table; `SMALLCAP_SYNTH` is a construction).
- **No book-to-market data before 2021** — `CHAR_MATCHED`'s industry/value
  dimensions degrade for 16 of 20 years of history.
- **No point-in-time sector history** (`sector_history` = 0 rows) — blocks
  the industry dimension of characteristic matching and the sector-concentration
  confound check entirely.
- **No promoter-entity list** (`promoter_entities` = 0 rows) — the
  promoter-related-transaction flag cannot be computed.
- **Three sessions are permanently and irrecoverably lost**: `nse_bulk_deals`
  2026-08-19 and 2026-08-27, `nse_block_deals` 2026-08-19, `fii_dii_cash`
  2026-08-19 — the historical NSE endpoint returns 503; only the rolling
  current-day file was ever fetchable, and these days were missed at the time
  (launchd not yet installed / a parse bug). Recorded permanently in
  `configs/sources.yml`'s `acknowledged_gaps` block rather than re-alerting
  forever.
- **BSE bulk/block deals have never been collected** (`existing_rows: 0` in
  `sources.yml`) — the BSE API route returns a 301 redirect to an error page
  even with the documented headers.
