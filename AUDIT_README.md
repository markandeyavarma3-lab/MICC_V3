# 1. Executive Summary

This is a **research data platform for Indian institutional disclosure data** (NSE bulk/block deals, FII/DII flows, insider filings, prices), deliberately scoped to produce *negative* results honestly. Solo project, 72 commits over 18 days, 9,409 lines of `src/` and 4,778 lines of tests.

**The genuine achievement is the statistical methodology and the reconstruction discipline**, not the software. `src/research/power.py`, `src/research/multiplicity.py` and `src/research/design.py` contain correct, well-derived, self-critical work — Bartlett-kernel serial inflation with label-overlap-aware lag, Gumbel-limit best-of-N noise bars with a degrees-of-freedom correction, MDE-before-fit. The warehouse rebuild (`src/warehouse/spine.py`, `src/warehouse/reconcile.py`) is verified against real data by tests that would actually fail.

**The software around it does not hold up.** Three findings dominate:

1. **The deal ingestion pipeline is currently broken.** `python -m src.ingest.land` — the only path that gets collected deals into the database — raises an unhandled `_csv.Error` on the first `PRICE` file in the archive. Reproduced. It has been broken since 2026-09-01, which is exactly why `deal_source_files` stops at 2026-08-28 while the archive holds sessions through 09-02.
2. **The project's own honesty instrument is self-satisfying.** `src/monitor/status.py` grades 12 steps from predicates matched by *status.py's own step-description strings*. Step 6.8 "Romano-Wolf stepdown" reads **VERIFIED** in `docs/STATUS.md`; the string `romano` exists in exactly one file in `src/` — `status.py` itself. Corrected, "nothing built" goes from 16 steps to 28.
3. **The entire governance layer is disconnected from the research it governs.** `ConfirmationGuard`, `ScanGuard`, `StudyDesign`, `commit_charge` are referenced by *no production module* — only by tests. `family_charge` holds **0 rows**. `src/research/selling.py` computes and prints a cohort mean on the full universe, which decision `0035` explicitly forbids outside the guard.

The repository's central thesis — *"the artefact exists" is not "the step works"* — is correct, well-argued, and **the project commits that error at least 15 times**, including inside the module written to detect it.

**Completeness: roughly 50%** by the project's own step ledger once its false positives are removed (36 of 73 steps wired-or-better). Phases 1–4 are substantially real. Phases 5, 6, 7 and the entire Track S scan track are configuration and prose.

# 2. Complete Project Architecture

## Purpose and users

Studies whether disclosed institutional activity in Indian equities contains repeatable information. Single user (the author). No orders, no money, no live path — and a test asserts this (weakly; see §9).

## Technology

Python 3.14, DuckDB 1.5.5 (analytics + relational marts), SQLite (append-only governance ledgers with real triggers), pandas/numpy/scipy, parquet on local disk. No frontend, no API, no server, no container. Scheduling by macOS `launchd` + cron. Reporting via Markdown → headless Chrome → PDF.

## The intended data flow

```
NSE endpoints
   │  src/archive/{stopgap,prices,insider,corporate_actions}.py
   ▼  raw bytes, sha256, gzip, never overwritten
data/raw/archive/**            + manifest.jsonl (append-only JSONL)
   │  src/ingest/{parse,land}.py            src/ingest/{bhavcopy,insider,corp_actions}.py
   ▼                                         ▼
research_prod.duckdb                       data/raw/collected/**.parquet
  institutional_deals_raw                    │
   │  src/identity/master.py                 │  src/warehouse/spine.py
   ▼  security_master / symbol_history       ▼
  deal_resolution (view)                   price_spine, price_spine_adj, fno_spine
   │                                         │
   │  src/mart/clean.py  ◄────────────────────
   ▼
  institutional_deals_clean   (237,340 rows, 5,877 eligible)
   │
   ▼  src/research/{measure,consensus,selling}.py
  MDE grids, power verdicts  →  stdout / decision records
```

## The flow as it actually runs

`scripts/collect_daily.sh` (3×/session via launchd + cron) executes:

`stopgap` → `prices` → `bhavcopy` → `corporate_actions` → `corp_actions` → `insider` → `ingest.insider` → **spine rebuild** → `health` → `backup.sh`

**`src/ingest/land.py`, `src/identity/master.py` and `src/mart/clean.py` are not in it.** Prices flow to the spine daily; **deals do not flow to the mart at all.** The relational half of the pipeline is manual, and currently non-functional (§8, BUG-1).

## Governance layer (parallel, and disconnected)

```
provenance.py ──► governance_prod.sqlite: artefact(81) artefact_edge(81) merkle_log(1)
families.py   ──► family_charge (0 rows)          ── never called outside tests
design.py     ──► StudyDesign gate                ── never constructed outside tests
split.py      ──► ConfirmationGuard / ScanGuard   ── never invoked outside tests
```

## Security boundaries

None in the software sense: single user, local filesystem, no auth, no network listener. The meaningful boundaries are *data* boundaries — raw archive is append-only, governance tables are trigger-protected, `RESEARCH_ENV` must be explicit.

## Phase 2 — Collection (steps 2.1–2.14)

**Objective** Capture rolling current-day NSE files before they roll over; land them.
**Inputs** 4 NSE endpoints.
**Processing** Fetch → sha256 → gzip → never overwrite → append manifest line.
**Outputs** 73+ archived `.gz` files, 136 manifest lines, `data/raw/collected/**.parquet`.
**Files** `src/archive/stopgap.py`, `src/archive/prices.py`, `src/archive/insider.py`, `src/archive/corporate_actions.py`, `src/ingest/parse.py`, `src/ingest/land.py`, `src/ingest/bhavcopy.py`, `src/ingest/publication.py`, `scripts/collect_daily.sh`.

**Status PARTIALLY COMPLETE / BROKEN** · **Quality 7/10** · **Correctness 3/10** · **Production readiness 2/10**

**Evidence of what works:** the archive/parse separation is a genuinely good design; the empty-envelope-is-a-failure rule in `insider.py` is a correct response to a real two-month silent loss; `prices.py` verifying the served `TradDt` against the requested date is right.

**Problems — this is the weakest phase and it is the one the project says matters most.**

- **`land()` crashes.** Reproduced:

  ```
  LAND FAILED: Error new-line character seen in unquoted field
  first offender: archive/PRICE/NSE/year=2026/month=08/PRICE_NSE_20260817_17e5c41a.csv.zip.gz
  ```

  `iter_archive()` globs every `*.gz` under `ARCHIVE` — 73 files, of which 41 are PRICE/INSIDER/CORPACT payloads that `parse_archive` labels `report_type="UNKNOWN"` and feeds to `parse_csv`. The module's headline claim ("a parse failure produces a recorded failure rather than an exception that stops a batch") is false: `parse_archive` catches only `OSError` around the gzip read.

- **Permanent, unrecoverable session loss.** Measured against the observed trading calendar (13 sessions, 2026-08-17 → 2026-09-02):

| source | captured | **permanently lost** |
|---|---|---|
| `nse_bulk_deals` | 11 / 13 | **2026-08-19, 2026-08-27** |
| `nse_block_deals` | 12 / 13 | **2026-08-19** (2026-08-25 was a legitimate `EMPTY_DAY`) |
| `fii_dii_cash` | 12 / 13 | **2026-08-19** |
| `nse_bhavcopy` | 13 / 13 | — |

  **~15% loss on the one data class the project says cannot be re-fetched at any price.** 2026-09-02 initially failed on all three sources and was recovered by a later run the same day — which is the system working as designed, and does not change the 08-19/08-27 losses.

- **`health.py` cannot see any of this.** `health.read()` tracks only `MAX(session_date)` per source. A gap in the middle of the series is invisible forever. The module written *because* 19 August was lost is structurally incapable of reporting that 19 August was lost — and `docs/HEALTH.md` currently reads **"all sources current"** with 0 sessions stale.
- **The alert never fires on a single-day loss.** `STALE_SESSIONS = 2`. On 2026-09-02 all three required sources failed and `health=0` was logged with status `ok`.
- **`collect_daily.sh` always exits 0.** The last statement in the block is `echo "backup=$?"`. launchd sees success even when `exit=1`, `prices=1`, `corpact=1` — all of which appear in that day's log.
- **`prices.collect()` never retries a mid-series failure.** `start = max(settled) + 1 day`, so a session that failed *before* a later success is skipped permanently, silently.
- **SSRF surface:** `src/archive/insider.py:214` fetches `r["xmlFileName"]` — a URL supplied by the remote API — through a `build_opener()` that includes `FileHandler`. No scheme check, no host allowlist. Low likelihood, trivially fixed, and it is the one place untrusted input reaches a fetcher.
- `sources.yml` asserts `also_store_parsed_parquet: true`. Nothing writes parsed parquet; `status.py`'s own note admits it.

# 5. End-to-End Feature Analysis

### Feature: "Collect a bulk deal and turn it into a research event"

`stopgap.capture()` ✅ → `archive/BULK/**.csv.gz` ✅ → `parse_all()` ❌ **crashes** → `land_file()` unreached → `institutional_deals_raw` stale at 08-28 → `clean.build()` never re-run → `measure.grid()` reads a 5-day-old mart.

**Verdict: BROKEN mid-path.** The path exists in code, has never been automated, and does not currently execute.

### Feature: "Point-in-time identity prevents ticker-recycling errors"

`master.build()` ✅ → `symbol_history` ✅ → `deal_resolution` view ✅ → `clean.py` stores `security_id` and `confidence` ✅ → **studies join on raw symbol, not `security_id`** ❌.

# 6. Architecture Review

## What is right

Package boundaries are clean and the dependency direction is correct: `common → {archive, ingest, warehouse, identity, mart, research, monitor}`, no cycles, `governance` depended on rather than depending. Every module is independently runnable with a `main()`. Configuration is externalised (where it is read). The SQLite-for-ledgers / DuckDB-for-marts split is justified by a real property (triggers) rather than taste.

## What is wrong

**The governance layer is a parallel universe.** Design gate, trial families, split guards, char-matched benchmarks and the six-benchmark set all exist as tested libraries with zero production call sites. This is not partial implementation — it is a complete second architecture that the first one never learned about. A reviewer reading `docs/` would conclude the project is disciplined by machinery; reading `src/` shows it is disciplined by the author remembering.

**Configuration is aspirational in two places and duplicated in five.** `sources.yml` and `scan.yml` — 551 lines — are parsed by nothing. HTTP constants exist in 5 copies. The bound that decides every PASS/FAIL exists in 2 copies, only one config-driven, and the config-driven one is unused.

**SQL is built by f-string interpolation throughout** — `spine.py`, `clean.py`, `master.py`, `measure.py`, `charmatch.py`, `reconcile.py`, `seed_deals.py`. Inputs are internal so injection risk is low, but it means schemas and column lists cannot be validated, and the same query text is rebuilt in three modules.

**`build_adjusted()` embeds its 4-source union in the query text and evaluates it four times** — discontinuity check, duplicate check, `COPY`, then a count. On 7.78 M rows that is 3 unnecessary full scans per daily run.

**`status.py` is a 695-line god function** (`steps()` returns 73 `Step`s with inline lambdas). It reads all of `src/`, both databases, the warehouse, the manifest, the backup destination and git. Its `consumed()` and keyword predicates search text that includes itself, which is the root of §21.

## What a strong senior engineer would change first

1. **Wire the guards, or delete them.** Either `measure/consensus/selling` construct a `StudyDesign` and call `charge()`, or the design gate and split guards come out of the repo. A tested-but-uncalled discipline framework is worse than none, because the documentation cites it.
2. **One eligibility implementation.** Delete `eligibility.py`'s view-building half; make `clean.py` the single definition and have it read `participants.yml` normalisation.
3. **Make `land()` part of `collect_daily.sh`,** after fixing `parse_all()` to filter by report type.
4. **Give `status.py` an out-of-band fact source** — a manifest file, or predicates that exclude `status.py` from `src_text`. A self-referential measurement instrument is not an instrument.
5. **Introduce a query layer.** `research_prod.duckdb` is accessed by 8 modules each opening their own connection and writing their own SQL; `mkt` and `rets` views are currently orphaned in the production database because `measure.grid()` leaks them.

# 8. Bugs and Failure Modes

### BUG-1 — CRITICAL — `land()` raises on the real archive

- **Location** `src/ingest/parse.py:111` via `:183`, `:193`
- **Root cause** `iter_archive()` returns every `*.gz` under `ARCHIVE`. `parse_archive()` assigns `report_type="UNKNOWN"` to PRICE/INSIDER/CORPACT payloads and routes them to `parse_csv`, whose `csv.reader` raises `_csv.Error` on binary/XML content. Only `OSError` is caught.
- **Trigger** Any run of `python -m src.ingest.land` since 2026-09-01.
- **Expected** A recorded `PARSE_FAILED`; the module docstring says so explicitly.
- **Actual** Unhandled exception, zero files landed.
- **Consequence** The deal pipeline has been dead for 2 days; the mart is stale; every research figure describes 2026-08-28.
- **Why no test caught it** All five landing tests monkeypatch `parse_all` to a synthetic tmp archive of well-formed CSVs. `test_parse_archive_never_raises_on_a_corrupt_file` writes non-gzip bytes, which hits the `OSError` branch.
- **Fix** Filter `iter_archive()` to `{BULK, BLOCK, FII_DII}` and wrap `parse_csv`/`parse_fii_dii` in `except Exception → PARSE_FAILED`. Add a test that runs `parse_all()` over `ARCHIVE` itself.

### BUG-2 — HIGH — Mid-series price sessions are never retried

- **Location** `src/archive/prices.py:269-278` (`collect()`)
- **Root cause** `start = max(settled_sessions()) + 1 day`. `settled` excludes FAILED, but `start` jumps past it.
- **Trigger** A transient failure at date X followed by a success at X+1 in the same run.
- **Consequence** Silent permanent hole in the price spine; the reconciliation gate cannot see it (scoped to `MICCV2_HORIZON`).
- **Fix** Derive `start` from the earliest unsettled weekday, not the latest settled one.

### BUG-3 — HIGH — `health.py` cannot detect a gap

- **Location** `src/monitor/health.py` `read()` — `if sid not in latest or d > latest[sid][0]`
- **Trigger** Any missed session followed by a successful one.
- **Actual** 2026-08-19 and 2026-08-27 are permanently lost; `docs/HEALTH.md` reads "all sources current", 0 sessions stale.
- **Fix** Compare the archived session set against the observed calendar; alert on any gap, not on recency.

### BUG-4 — HIGH — `collect_daily.sh` always exits 0

- **Location** `scripts/collect_daily.sh`, final statement `echo "backup=$?"` inside the redirected block.
- **Consequence** launchd and cron never see a failure. The 2026-09-02 morning log contains `exit=1`, `prices=1`, `corpact=1`, and the job reported success.
- **Fix** Accumulate a failure flag and `exit "$rc"`.

### BUG-5 — HIGH — Studies join prices on the raw symbol

- **Location** `src/research/measure.py:157`, `consensus.py:116`, `selling.py:68`
- **Root cause** `security_id` is computed and stored, then not used.
- **Consequence** A recycled ticker attributes one company's deal to another company's prices — `master.py`'s docstring measures this at 331 symbols mapping to more than one ISIN, and calls it "worse and less discussed".
- **Fix** Join `institutional_deals_clean.security_id → symbol_history` valid at `trade_date`, then to the spine.

### BUG-6 — MEDIUM — `migrate_sqlite` rollback is a no-op

- **Location** `src/common/migrate.py:114-123` — `executescript` implicitly commits first.
- **Consequence** A migration failing halfway leaves the schema half-applied and unrecorded; the next run replays it from the top.
- **Fix** Split statements (the function already exists — `split_statements`) and drive an explicit transaction, as the DuckDB path does.

### BUG-7 — MEDIUM — `test_status_is_not_stale` is structurally red

- **Location** `tests/test_status.py:21`
- **Root cause** `STATUS.md` embeds `backup.taken_at`, which changes 3× per day; `collect_daily.sh` runs `backup.sh` but not `status.py`.
- **Actual** Failing at audit time: committed `2026-09-02 13:15 UTC` vs derived `06:05 UTC`.
- **Consequence** The README's "411 pass" is false, and a permanently-red test trains its reader to ignore it.
- **Fix** Exclude volatile timestamps from the comparison, or regenerate `STATUS.md` in the daily job.

### BUG-8 — MEDIUM — 16 of 37 corporate actions carry no factor and are never applied

RIGHTS (10) and DEMERGER (3) are NULL by design; UNPARSED (3) need a human and there is no queue — the "NEEDS A HUMAN" list is printed to a log. TRIVENI's −41.6% demerger sits unadjusted in `price_spine_adj` today.

### BUG-9 — LOW/MEDIUM — Survivorship in the forward-return construction

`src/research/measure.py:86` (`_returns_sql`) filters `WHERE close > 0 AND open > 0` *before* assigning the session index, then takes `LEAD(close, N)`. A delisted or suspended name yields NULL and is dropped by `dropna`. At 252 sessions only survivors contribute. `confounds.yml` lists survivorship as blocking; the code does not address it.

### BUG-10 — LOW — Orphan views in the production database

`measure.grid()` leaks `rets` and `mkt` onto the persistent `research_prod.duckdb` connection. Both are present right now. `status.py` had to add a per-table try/except because of it — the monitoring module working around the research module's side effects.

# 14. AI/ML Audit

**There is no AI/ML component** — no model, no LLM, no inference, no prompts, no embeddings, no training. Do not claim otherwise in any interview.

The equivalent technical core is **statistical methodology**, and it deserves a real assessment: **8/10**, the highest score in this audit.

**What is genuinely strong:**

- **`cohort_collapse` as the primary estimator, not a robustness step.** Collapsing overlapping events to monthly cohort means defeats cross-sectional dependence by construction. The docstring shows the receipts: naive t = +11.61, cohort t = +3.61, bootstrap 95% CI [−2.46%, +22.81%].
- **`serial_inflation` with a label-overlap-aware lag.** The best piece of reasoning in the repository. The Newey-West rule of thumb depends only on n and picked K=9 against a true overlap of 252, understating variance inflation fivefold and manufacturing a POWERED verdict. `label_periods` fixes it and the fix *removed the project's headline result*. The Bartlett taper is correctly floored at 1.0 with the right justification.
- **`expected_max_null_t` via the Gumbel limit**, with a correctly-identified sidedness bug (`max(z)` = 2.693 vs `max|z|` = 2.922 at N=171) and a degrees-of-freedom correction that moves the bar the *anti*-conservative way if omitted.
- **MDE-before-fit, and UNDERPOWERED outranking a significant p-value.** `verdict()` returns UNDERPOWERED even when p < 0.05, on the correct grounds that a study whose detection floor exceeds the plausible effect carries no information.
- **Three of four pre-registered studies were killed by this machinery.** The strongest possible evidence it is real.

**What is weak:**

- **The benchmark is undeclared.** Every result is measured against `avg(ret)` over the whole spine — an unweighted mean including ETFs, penny stocks and an 85,575% bad print, with median |value| of 24.44% at 12 months. `benchmarks.yml` specifies six benchmarks and designates `CHAR_MATCHED` PRIMARY; none is used.
- **Survivorship is unaddressed** in the forward-return construction (BUG-9), while `confounds.yml` lists it as blocking.
- **`mde()` rounds `n_eff` to an integer**, discarding precision in the quantity the whole verdict turns on.
- **`selling.py` estimates an effect outside the guard**, which decision `0035` forbids in writing.
- **None of the confound checklist is implemented.** `confounds.yml` (198 lines) is read only by `design.py`, which no study constructs.
